# Заметки по коду MdGlimpse

Разбор мест, где язык или устройство библиотеки что-то решают. Это не
документация пользователя — она в [README.md](README.md), — а записки
для того, кто читает исходники: своего рода экскурсия по коду.

Проект писался в том числе как учебный материал по Rust для владельца
(фон — C#), отсюда подробность разборов. Если вы просто хотите смотреть
markdown, вам сюда не надо.

---

## Почему egui, а не Tauri / Iced / Slint

| | Что получаем | Чем платим |
|---|---|---|
| **egui** (взят здесь) | Один бинарник, ноль системных зависимостей в рантайме, весь код на Rust | Рендер текста свой, не CSS: типографика проще, чем в браузере |
| **Tauri 2** | HTML/CSS-рендер, тот же markdown-CSS что на GitHub, Android/iOS из коробки | Нужен WebView2 (Win) / WebKitGTK (Linux); UI пишется на JS, Rust только бэкенд |
| **Iced** | Чистый Rust, Elm-архитектура, есть встроенный виджет markdown | Экосистема мельче, API ещё заметно меняется между версиями |
| **Slint** | Декларативный UI, очень лёгкий | Markdown придётся рисовать самому |

Для «показать .md и всё» egui выигрывает по соотношению кода к результату.
Если позже захочется вёрстку уровня GitHub и Android — переезд на Tauri
затронет только слой UI: модуль `document.rs` останется как есть.

## Rust-концепции, которые здесь реально работают

Не абстрактные примеры из книжки, а места в этом коде, где язык что-то решает.

### `Option` вместо null — `app.rs`

```rust
document: Option<Document>,
```

Файл может быть не открыт. В C# это `Document?` и надежда, что вы не забыли
проверку. Здесь до `Document` физически нельзя добраться, не разобрав `Option`:

```rust
let Some(document) = document.as_ref() else {
    draw_placeholder(ui);
    return;
};
```

`let-else` — «либо распаковали, либо выходим». Ниже по коду `document` уже
обычное значение, проверки не нужны.

### `Result` вместо исключений — `document.rs`

```rust
pub fn load(path: &Path) -> Result<Self, DocumentError>
```

Ошибка — это возвращаемое значение, а не выброшенное. `?` пробрасывает её
наверх одним символом. Компилятор не даст проигнорировать `Result` молча.
Забавная деталь: `?` работает и с `Option`:

```rust
std::fs::metadata(path).ok()?.modified().ok()
```

### Чужой шрифт — тоже зависимость

Кнопка закрытия поиска рисовалась белым квадратом. Символа `✕` (U+2715)
нет в Inter, и он должен был найтись в запасном `emoji-icon-font` —
в его таблице символов этот код есть. Но там он отображён в глиф
номер ноль, то есть в `.notdef`: запись в таблице есть, глифа нет.

Отсюда два вывода, оба практических. Первый: символ в тексте — это
внешняя зависимость не хуже крейта, только без версий и без компилятора,
который проверит. Второй: проверять покрытие надо не по таблице шрифта,
а спрашивая ту библиотеку, которая будет рисовать, — у egui для этого
есть `Fonts::has_glyph`.

Поэтому в проекте есть константа `TEXT_SYMBOLS` со всеми символами,
которые интерфейс подставляет в текст, и раздел в отладочной галерее,
который каждый из них проверяет. Вердикт печатается словами, а не
галочкой: значок галочки сам может оказаться непокрытым, и тогда отчёт
соврёт о самом себе.

### Изоляция хрупкого — `rendered_probe.rs`

Самый поучительный модуль в проекте, и написан он от безвыходности.

Подсветить найденное в отрендеренном виде «по-хорошему» нельзя:
`egui_commonmark` рисует каждый фрагмент текста своим `ui.label(..)`
и выбрасывает `Response`, а `show` возвращает `InnerResponse<()>`.
Публичного способа узнать, где на экране оказалось слово, не существует.
Единственный путь — прочитать уже нарисованное из списка фигур слоя,
то есть опереться на **внутреннее устройство** чужой библиотеки, а не
на её обещания.

Такой код опасен не тем, что сломается, а тем, что сломается **молча**:
после обновления egui подсветка просто перестанет появляться, и ни один
тест этого не заметит. Отсюда три правила, по которым он написан:

1. **Он живёт в одном файле.** Наружу торчат две функции. Если однажды
   придётся всё выбросить, выбрасывать нужно будет один модуль,
   а не выковыривать допущения из десяти мест.
2. **Допущения перечислены явно.** В заголовке модуля списком: что
   `Context::graphics` отдаёт список фигур, что текст приезжает как
   `Shape::Text`, и так далее. Это не украшение — это то, что надо будет
   перепроверить при обновлении.
3. **У него есть проверка живости.** Если после отрисовки документа
   в слое не нашлось ни одного текстового шейпа — это не «совпадений
   нет», а сломанная связка. Модуль возвращает ошибку, приложение пишет
   об этом в полосе поиска.

Rust помогает здесь типом: `locate` возвращает не `Vec<Rect>`, а
`Result<Vec<Rect>, ProbeBroken>`. «Ничего не нашлось» и «механизм
сломался» — разные значения разных вариантов, и вызывающий код обязан
их различить. Забыть про второй нельзя: компилятор не даст.

### Свой тип ошибки — `DocumentError`

```rust
pub enum DocumentError {
    Io(std::io::Error),
    NotText(NotTextReason),
    TooLarge { size: u64, limit: u64 },
}
```

Сначала здесь был голый `std::io::Error`, и «файл не читается» было
не отличить от «файл не текстовый». Собственный enum разделяет случаи,
а варианты умеют носить с собой данные — `TooLarge` прямо в себе держит
размер и предел, из которых потом собирается сообщение.

Такой тип состоит из четырёх частей, и в проекте они написаны руками,
чтобы было видно, из чего он складывается:

- сам `enum` — перечень того, что может пойти не так;
- `impl Display` — текст для человека;
- `impl std::error::Error` с методом `source()` — «причина под причиной»,
  чтобы внешний код мог раскрутить цепочку, не зная наших внутренностей;
- `impl From<std::io::Error>` — ради него `?` продолжает работать как
  раньше: оператор сам зовёт `From::from` для ошибки, которую пробрасывает.

В настоящем проекте всё это обычно генерирует макрос `thiserror`.
Один раз полезно написать вручную, чтобы понимать, что он генерирует.

### Срезы вместо копий — построчный индекс

```rust
line_ranges: Vec<Range<usize>>,
```

Режим «Исходник» показывает файл построчно и рисует только видимые строки.
Напрашивается `Vec<String>` — но это копия всего текста, то есть удвоение
памяти на ровном месте. Вместо этого хранятся байтовые **диапазоны** внутрь
уже имеющейся строки, а `line(i)` отдаёт `&str` — окно в чужие байты:

```rust
pub fn line(&self, index: usize) -> &str {
    self.line_ranges
        .get(index)
        .map_or("", |range| &self.source[range.clone()])
}
```

Время жизни здесь выводится автоматически: `&str` не может пережить
`&self`, из которого получен, и компилятор это гарантирует. В C# такой
`Span<char>` пришлось бы держать в голове самому.

### Enum как тип-сумма — `ViewMode`

```rust
enum ViewMode { Rendered, Source }
```

Не флажок `bool is_source` и не набор констант. Значение — ровно один из
вариантов. `match` обязан покрыть все: добавите третий режим (скажем,
side-by-side) — компилятор сам приведёт вас во все места, которые надо дописать.
Это главный практический выигрыш от enum'ов Rust.

### Владение и заимствование — самая частая точка спотыкания

В `Document::reload` нельзя написать так:

```rust
self.source = read_text(&self.path)?;          // ок
self.rendered = absolutize_links(&self.source, self.path.parent());  // ок
```

...но вот это уже нет, если справа читать то, во что слева пишем.
Поэтому в коде сначала локальные переменные, потом присваивание.
Правило: **либо одна изменяемая ссылка, либо сколько угодно неизменяемых**,
и проверяется это на этапе компиляции.

### Деструктуризация ради заимствования — `toolbar()` и `content()`

```rust
let Self { document, mode, auto_reload, .. } = self;
```

Замыкание, переданное в `Panel::show`, иначе одолжило бы `self`
целиком. Разобрав структуру на поля, мы одалживаем их по отдельности —
и можем одновременно читать `document` и менять `cache`.

Тот же мотив у структуры `Actions`: пока рисуется тулбар, поля `self` заняты,
вызвать `self.open_dialog()` изнутри замыкания нельзя. Собираем намерения
в простой флажковый тип, выполняем после. Это не костыль, а типичный для Rust
приём — разделить «что решили» и «что делаем».

### `&str` и `String`

`&str` — окно в чужие байты, `String` — владеющий буфер. В `absolutize_links`
разбор идёт по срезам без единого копирования, и только результат собирается
в новую `String`. Возврат `&'static str` из `button_text()` — строка живёт
в бинарнике, копировать нечего.

### Immediate mode GUI

Отдельная идея, не про Rust: `App::ui()` вызывается каждый кадр и заново
описывает весь интерфейс. Виджетов-объектов не существует — `ui.button()`
это одновременно «нарисуй» и «был ли клик». Отсюда правило: всё состояние
живёт в вашей структуре, а не в UI. Именно поэтому здесь нет ни callback'ов,
ни подписок, ни `Rc<RefCell<...>>`.

В egui 0.36 приложение получает корневой `egui::Ui`, а не `egui::Context`,
и панели прикрепляются к нему: `egui::Panel::top("toolbar").show(ui, ..)`,
`egui::CentralPanel::default().show(ui, ..)`. В более старых примерах
из интернета вы встретите `fn update(&mut self, ctx: &egui::Context, ..)`
и `TopBottomPanel::top(..).show(ctx, ..)` — это API до 0.36.
