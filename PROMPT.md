Скопируйте текст ниже (от разделителя) в Claude Code, запущенный в корне
проекта. Он рассчитан на работу по этапам с остановками — не запускайте

## Промпт: Этап 0 — привести проект в рабочее состояние

```
Прочитай CLAUDE.md и ROADMAP.md.

Этот код я не компилировал ни разу — он написан «вслепую» под egui 0.36 и
egui_commonmark 0.25. Твоя первая задача — довести его до состояния, когда
он собирается и работает. Скорее всего есть расхождения с реальным API:
переименованные методы, изменившиеся сигнатуры, отсутствующие фичи крейтов.

Работай так:

1. Убедись, что структура проекта верна: Cargo.toml в корне, исходники
   в src/. Файлы main.rs, app.rs, document.rs должны лежать именно в src/.

2. Запусти `cargo build`. Каждую ошибку компиляции разбирай по документации
   крейта, а не угадыванием. Если не уверен в API — сверься с исходниками
   в ~/.cargo/registry или с docs.rs. Не заменяй непонятный вызов на
   «примерно похожий».

3. Особое внимание к местам, где я мог ошибиться:
   - `egui::TextEdit::multiline(&mut &str)` для режима «только чтение» —
     проверь, что `&str` действительно реализует `TextBuffer` в 0.36.
     Если нет, найди актуальный способ показать нередактируемый текст,
     который при этом можно выделять и копировать.
   - `CommonMarkViewer::new().show(ui, &mut cache, text)` — сигнатура в 0.25.
   - Фичи `egui_extras`: нужны `image` и `file`. Проверь, что фича `file`
     существует и что file:// URI действительно грузятся.
   - `ctx.style_mut(|style| style.url_in_tooltip = true)` — есть ли это поле.
   - `rfd` под Windows: собирается ли с дефолтными фичами.

4. Прогони `cargo clippy --all-targets -- -D warnings` и почини всё.

5. Запусти приложение и проверь руками по чек-листу Этапа 0 из ROADMAP.md.
   Отдельно проверь кириллицу: и в отрендеренном тексте, и в моноширинном
   исходнике. Если встроенные шрифты egui её не покрывают — подключи
   системный шрифт через `ctx.add_font`, но сначала проверь, что проблема
   реально есть.

6. Отметь выполненные пункты в ROADMAP.md.

Не берись за Этап 1, пока Этап 0 не закрыт полностью. В конце покажи:
что было сломано, что исправил, и что из этого стоит знать мне как
человеку, изучающему Rust.
```

## Промпт: Этап 1 — сделать из бинарника приложение для Windows

Запускать только после закрытого Этапа 0.

```
Прочитай CLAUDE.md и ROADMAP.md, раздел «Этап 1».

Сейчас MdGlimpse — просто exe в папке. Нужно, чтобы это было нормальное
Windows-приложение: с иконкой, запускаемое из меню «Пуск», и главное —
чтобы двойной клик по .md файлу открывал его в MdGlimpse.

Сделай по частям, показывая мне результат после каждой.

### 1.1 Иконка и метаданные

- Нарисуй простую иконку и положи её как assets/mdglimpse.ico со всеми
  нужными размерами (16, 32, 48, 64, 128, 256). Если сгенерировать не можешь —
  сделай SVG, скажи мне, и я конвертирую сам.
- Подключи её через build.rs (крейт `winresource`), гейт по `#[cfg(windows)]` /
  условной зависимости в `[target.'cfg(windows)'.build-dependencies]`.
- Туда же метаданные: FileDescription, ProductName, версия, копирайт.
- Задай ту же иконку окну через `ViewportBuilder::with_icon`.
- Проверь: иконка видна у exe в проводнике, на панели задач и в заголовке.

### 1.2 Ассоциация с .md

Требования:
- Регистрация **только в HKCU**, без прав администратора.
- Ничего не пишется в реестр само по себе. Регистрация — явное действие
  пользователя из UI.

Реализация (проверь актуальность, я мог напутать в деталях):

    HKCU\Software\Classes\MdGlimpse.markdown
        (Default)                        = "Markdown Document"
    HKCU\Software\Classes\MdGlimpse.markdown\DefaultIcon
        (Default)                        = "<путь к exe>,0"
    HKCU\Software\Classes\MdGlimpse.markdown\shell\open\command
        (Default)                        = "\"<путь к exe>\" \"%1\""
    HKCU\Software\Classes\.md\OpenWithProgids
        MdGlimpse.markdown               = ""   (пустое REG_SZ)

После записи дёрнуть SHChangeNotify(SHCNE_ASSOCCHANGED, SHCNF_IDLIST, ...),
иначе проводник не увидит изменений до перезахода в систему.

- Путь к exe брать из `std::env::current_exe()`, не хардкодить.
- Отдельная функция снятия регистрации, удаляющая ровно то, что создала.
- Всё это в новом модуле `src/platform/windows.rs`, за `#[cfg(windows)]`.
  Рядом заготовка `src/platform/linux.rs` с тем же публичным интерфейсом
  (`register()` / `unregister()` / `is_registered()`) — там это .desktop файл
  и `xdg-mime`. Под macOS — заглушки, возвращающие «не поддерживается».
- Модуль `platform` не должен зависеть от egui.
- Крейты: `winreg` или `windows-registry` для реестра, `windows` для
  SHChangeNotify. Только под таргет windows.

Важно понимать и объяснить мне в итоге: Windows 10/11 не позволяет программе
молча назначить себя обработчиком по умолчанию. Мы можем только
зарегистрировать ProgId, после чего MdGlimpse появится в «Открыть с помощью»,
а выбор по умолчанию пользователь делает сам через системный диалог.
Отрази это в тексте UI честно — не обещай того, чего не будет.

### 1.3 UI для регистрации

- Добавь в тулбар меню (`ui.menu_button`) с пунктами:
  «Открыть…», «Недавние» (пока пусто, задел на Этап 2), разделитель,
  «Связать с .md файлами», «Убрать связь», разделитель, «О программе».
- Показывай текущее состояние: зарегистрировано или нет.
- Результат операции — понятным русским текстом в UI, не паникой.

### 1.4 Инсталлятор

- Скрипт Inno Setup в `installer/mdglimpse.iss`:
  установка в {localappdata}\MdGlimpse (без прав админа), ярлык в «Пуск»,
  опциональная галка ассоциации с .md, корректная деинсталляция
  с удалением ключей реестра.
- Короткая инструкция сборки инсталлятора в README.

В конце обнови README и ROADMAP.md.
```

## Промпт: Этапы 2–3 — состояние и навигация

```
Прочитай CLAUDE.md и ROADMAP.md. Делаем Этап 2 и Этап 3.

### Этап 2 — сохранение состояния

Включи фичу persistence у eframe и реализуй `App::save` / восстановление
в `MdGlimpseApp::new`. Сохраняем: тему, режим просмотра, ширину колонки,
масштаб, галку слежения, список из 10 недавних файлов, геометрию окна.

Заведи отдельную структуру настроек с serde-производными, не сериализуй
всё приложение целиком. Несуществующие файлы вычищай из списка недавних
при загрузке.

### Этап 3 — оглавление и навигация

Убираемая боковая панель с оглавлением:
- Заголовки вытаскивай разбором markdown через pulldown-cmark
  (он уже в дереве зависимостей как транзитивная зависимость
  egui_commonmark — но объяви его явно, полагаться на транзитивную нельзя).
- Разбор — в document.rs или новом модуле outline.rs, без зависимости от egui.
  Структура вида { уровень, текст, якорь }. Покрой юнит-тестами:
  вложенность, дубликаты заголовков, заголовки с кодом и ссылками внутри.
- Панель — `egui::SidePanel::left`, сворачивается кнопкой в тулбаре и Ctrl+B,
  состояние сохраняется между запусками. Ширина регулируется мышью.
- Клик по пункту прокручивает документ к заголовку. В egui это делается через
  `Response::scroll_to_me` или `ui.scroll_to_rect` — разберись, как связать
  пункт оглавления с позицией заголовка внутри CommonMarkViewer. Если
  egui_commonmark не отдаёт позиции заголовков, честно скажи мне об этом
  и предложи варианты, а не имитируй работу приблизительной прокруткой.

Переходы по локальным ссылкам:
- Клик по `[текст](другой.md)` открывает соседний файл в том же окне.
- Стек истории, кнопки «назад»/«вперёд» в тулбаре, Alt+← и Alt+→.
- Внешние http(s) ссылки по-прежнему открываются в системном браузере.
- Учти, что document.rs переписывает относительные пути в file:// URI —
  обработчик кликов должен уметь превращать их обратно в пути.

Делай по одной подзадаче, показывай результат. После каждой —
полный набор проверок из CLAUDE.md.
```

## Как этим пользоваться

1. Разложите файлы по структуре из README, положите рядом `CLAUDE.md`,
   `ROADMAP.md`, `PROMPT.md`.
2. `git init` и коммит **до** запуска Claude Code. Иначе не с чем будет
   сравнивать и некуда откатываться.
3. Запускайте этапы по очереди, каждый — в свежей сессии.
4. После каждого этапа — коммит с осмысленным сообщением.

Отдельно про Этап 0: там довольно вероятны правки в нескольких местах сразу.
Просите показывать дифф и объяснять, что именно было не так, — это ровно
тот материал, на котором язык и усваивается.
