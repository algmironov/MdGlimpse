# ROADMAP

Живой документ. Сделанный пункт отмечается `[x]` и коротким комментарием
о том, что всплыло по дороге.

---

## Этап 0 — сборка и базовая работоспособность

- [ ] Проект собирается: `cargo build --release` без ошибок и предупреждений
- [ ] `cargo clippy --all-targets -- -D warnings` чисто
- [ ] Приложение запускается без аргументов и показывает заглушку
- [ ] Приложение запускается с путём к файлу и сразу его отображает
- [ ] Переключение рендер ↔ исходник работает (кнопка и `Ctrl+E`)
- [ ] Drag & drop файла в окно открывает его
- [ ] Кириллица отображается корректно в обоих режимах, включая моноширинный
      шрифт в исходнике (если нет — подключить системный шрифт через `add_font`)
- [ ] Картинка рядом с `.md` файлом отображается в рендере
- [ ] Юнит-тесты в `document.rs` проходят

## Этап 1 — Windows как настоящее приложение

Главный этап. Без него это не программа, а бинарник в папке.

- [ ] **Иконка приложения.** `.ico` встраивается в `.exe` через `build.rs`
      (крейт `winresource` или `embed-resource`). Иконка видна в проводнике,
      на панели задач и в заголовке окна.
- [ ] **Метаданные исполняемого файла**: название, версия, копирайт —
      видны в свойствах файла в проводнике.
- [ ] **Ассоциация с `.md`.** Регистрация ProgId в `HKCU\Software\Classes`
      (без прав администратора). После этого mdview появляется в меню
      «Открыть с помощью», а пользователь может назначить его по умолчанию.
      Детали реализации — в PROMPT.md.
- [ ] **Пункт меню «Зарегистрировать mdview для .md файлов»** внутри
      приложения, плюс «Отменить регистрацию». Никакой самодеятельности
      при первом запуске.
- [ ] **Открытие нескольких файлов** — при передаче нескольких путей в argv
      открывается первый, остальные игнорируются с понятным сообщением
      (либо, если сделаны вкладки — открываются все).
- [ ] **Инсталлятор.** Скрипт Inno Setup: установка в `%LOCALAPPDATA%\mdview`,
      ярлык в меню «Пуск», регистрация ассоциации, корректное удаление.
- [ ] Linux-паритет: `.desktop` файл и MIME-регистрация для `text/markdown`.

## Этап 2 — сохранение состояния

- [ ] Настройки переживают перезапуск: тема, режим просмотра, ширина колонки,
      масштаб, галка слежения за файлом. Через механизм persistence в eframe
      (`App::save` + фича `persistence`).
- [ ] Позиция и размер окна восстанавливаются.
- [ ] Список недавних файлов (10 штук) в меню, с проверкой существования.

## Этап 3 — навигация по документу

- [ ] **Убираемая боковая панель с оглавлением.** Заголовки вытаскиваются
      разбором markdown, клик прокручивает к нужному месту. Панель
      сворачивается кнопкой и `Ctrl+B`, состояние сохраняется.
- [ ] Подсветка текущего раздела в оглавлении при прокрутке.
- [ ] **Переходы по локальным ссылкам**: `[глава 2](chapter2.md)` открывает
      соседний файл. Стек истории, кнопки «назад» / «вперёд», `Alt+←` / `Alt+→`.
- [ ] Переходы по якорям `#заголовок` внутри документа.

## Этап 4 — работа с текстом

- [ ] **Поиск по документу** (`Ctrl+F`): панель поиска, подсветка совпадений,
      переход по `Enter` / `F3`, счётчик «3 из 17». Работает в обоих режимах.
- [ ] Номера строк в режиме исходника.
- [ ] Копирование блока кода одной кнопкой в отрендеренном виде.

## Этап 5 — экспорт

- [ ] Экспорт в HTML: `pulldown-cmark` плюс встроенный CSS-шаблон,
      картинки инлайнятся в base64 либо копируются рядом.
- [ ] Печать / PDF — через экспорт в HTML и системный браузер,
      либо отдельным рендерером. Решить, что дешевле, до реализации.

## Этап 6 — качество

- [ ] Замена опроса `mtime` на крейт `notify` (поток + `std::sync::mpsc`).
      Отдельно проверить поведение при удалении и пересоздании файла —
      многие редакторы сохраняют именно так, а не записью на месте.
- [ ] Настройка шрифта и его размера в UI.
- [ ] Режим «две панели»: рендер и исходник рядом, синхронная прокрутка.
- [ ] Вкладки для нескольких открытых файлов.
